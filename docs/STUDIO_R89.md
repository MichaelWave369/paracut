# ParaCut Studio R8.9 · REEL / CineSwarm Original Shot Intake

**Release boundary: first actual local-to-local import into a native ParaCut Studio timeline.** This is neither a film generator nor an automatic publisher.

## What ParaCut can now do

ParaCut Studio's **Project Media** panel has a collapsed **REEL Originals · Verified-Byte Media Import** section. You can import a genuine REEL Pilot 001 S01 delivery master **only after** you explicitly choose **two local files**:

1. The real `1280×720 / 24fps` master MP4 already produced and stored in CineSwarm.
2. An **unsigned** `REEL_P001_REAL_MEDIA_EVIDENCE_V1` JSON sidecar exported independently by [CineSwarm PR #6](https://github.com/MichaelWave369/CineSwarm/pull/6) from that local master asset UUID.

The CineSwarm command is run separately in the operator's **already installed** native environment:

```bash
python -m cineswarm.reel_media_evidence \
  --data-root ./parallax-cineswarm-data \
  --artifact-id <REAL-MASTER-ARTIFACT-UUID> \
  --out reel-p001-shot-one-evidence.json
```

This native command reads the existing actual generated master/native MP4s, rehashes both, runs ffprobe, verifies its existing SQLite receipt ledger and optional exact-hash human QC. It creates a JSON reference; it does not make or copy footage.

In ParaCut:

1. Open Studio's **Project Media → REEL Originals · Verified-Byte Media Import** panel.
2. Select the evidence JSON and the exact existing master MP4. Click **Inspect & hash MP4**. This is user-controlled browser `WebCrypto SHA-256` over the selected bytes, with a 256 MiB media cap and 64 KiB JSON cap. It refuses malformed, oversized, fake-model, non-MP4-signature, wrong-byte-count and wrong-hash files. It also requires the JSON to **deny all release, source-IP, voice and music clearance authority**.
3. A verified match displays the claimed human review status: **PENDING_REVIEW / ACCEPT / REJECT / REVISION_REQUESTED**. Even ACCEPT is only exact-hash footage QC, not public release. There is no silent import.
4. Click **Add exact master to Video 1 timeline**. ParaCut uses its normal browser media probe for actual duration. It requires duration to be within 1.5 seconds of the CineSwarm sidecar's claimed length, then invokes actual native `asset.added`, `clip.appended`, and `clip.source-audio.muted` edits in a staged state. All three result in standard ParaCut ledger receipts and undo checkpoints, then the app commits state and creates an object URL for that exact chosen MP4. Source sound is muted by default until the editor deliberately unmutes or adds cleared soundtrack/voice via A1/A2.
5. The new video is a **real V1 source clip**, visible in Program Monitor, trim/split/transition/color/title-ready just like other ParaCut footage. Save Draft via ParaCut's standard control. Its `paracut.studio.draft.v3` media asset record persists an `reelEvidence` tag with media and native SHA-256 hashes, source plan hash, claimed original-review state, expected backend and explicit `publicReleaseAuthorized:false`. The `asset.added` receipt records the master digest with `reel_unsigned_source:true`.
6. As always, ParaCut drafts **never embed the video bytes**. Reopen your project and explicitly relink the original master MP4 through ParaCut's existing import media control. The provenance tag is carried by the asset reference, not a promise that relinking a random file is trustworthy.

## Evidence and safety boundaries

- An unsigned JSON file paired with a matching MP4 **only demonstrates file-byte consistency with the declared hash**. ParaCut cannot authenticate that the footage was generated by CineSwarm, that the renderer was licensed, that the operator consented, or that the content is cleared for publication. The file tag is **declared evidence**, not a cryptographic signature or a rights receipt.
- REEL's static GitHub Pages and this ParaCut Studio never invoke `/v1/jobs`, scrape or proxy other TV streams, contact a local GPU coordinator, install weights, upload a movie, or grant a public channel. The entire procedure requires separate user file selections and two explicit button clicks.
- Human `ACCEPT` verifies only CineSwarm's claimed review of that same artifact SHA; it is **not** ParaCut edit approval, a final credits check, copyright clearance or REEL publisher permission. Reject/revision states remain clearly visible rather than treated as released footage.
- Three ordinary Studio edit receipts and the `reelEvidence` asset tag do **not** replace CineSwarm's source receipt chain. The provenance tag comes from editable unsigned JSON and should always be read as a claim.
- ParaCut's draft import validates that the `reelEvidence` tag cannot claim any public release authority. Undo/redo uses the existing snapshot machinery and ordinary project export/import preserves the tag.

## Manual validation

After merge, open ParaCut Studio over HTTPS. Test a genuine complete first-shot master MP4 and a matching native sidecar, check correct byte hash, and explicitly commit V1 timeline. Save/reopen Draft, reselect that exact original file, and inspect clips, source audio mute and imported evidence tag. Repeat with altered hashes, changed source files and forged publishing flags to ensure denial. Browser playback depends on actual supported MP4 codecs.

No tested CI synthetic video, mock ftyp bytes or planning JSON should be represented as model-rendered footage. **No REEL-original movie or new RCTV channel is published by this change.**
